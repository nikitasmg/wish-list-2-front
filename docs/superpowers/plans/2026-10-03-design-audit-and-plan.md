## 1. Принятые решения (3 октября)

Решения согласованы с владельцем продукта. Макет поправлен под них
(версия 18 канваса), чтобы не было двух правд.

### Р1. Раскладка — ряды с колонками, формат блоков v3

Макет (`BuilderResize`, `BuilderDrag`): страница — это ряды. В ряду 1–3
колонки, пропорции 1:1 / 2:1 / 1:2 (разделитель прилипает к ним), высота
«одинаковая / по содержимому», расстояние S/M/L, порядок на телефоне
«друг под другом / правая — первой», кнопка «Разделить ряд на блоки».
Одиночный блок — «узкий / на всю ширину». Перенос: «между блоками — вставится
ниже, у бокового края — встанет рядом и соберёт ряд».

Сейчас: `row`, `col: 0|1`, `colSpan: 1|2` (`shared/grid.ts`), двух колонок
максимум, пропорция всегда 1:1, настроек ряда нет.

**Решение:** блоки сохраняют `row`/`col`/`colSpan` (`col` 0–2, `colSpan` 1–3),
а рядом с ними в том же `PUT /wishlists/:id/blocks` едет массив `rows`
с настройками по индексу ряда. Блоки и ряды пишутся одним запросом под одним
`If-Match`, поэтому индекс ряда не разъедется. Ряд без записи в `rows`
получает значения по умолчанию, так что v2 читается без миграции данных.
Ряды как отдельные сущности с id не делаем: это ломает `grid.ts`, шаблоны,
примеры и прод-данные.

### Р2. Левая колонка — рельс

Узкий рельс «Добавить блок / Структура / Оформление / Отменить», выезжающие
панели и «+» между блоками с поповером и превью. Постоянная библиотека из
`7cb28c7` переезжает в панель «Добавить блок». `Builder.dc.html` в макете
переведён на рельс.

### Р3. Вкладки правой панели — «Блок (Ряд) / Оформление / Доступ»

Поля бывшей «Страницы» разносим: название и подзаголовок правятся прямо
в обложке, дата и повод — в инспекторе обложки, ссылка — в «Доступе».
`Builder` и `InlineEdit` в макете приведены к этим вкладкам.

### Р4. Статусов у вишлиста нет

Черновиков, публикации и архива не делаем. Вишлист открыт по ссылке, как
сейчас. Из макета убраны табы «Активные / Черновики / Архив», статус-пилюли
на карточках, «не опубликован · видите только вы». Кнопка «Опубликовать»
в шапках заменена на «Поделиться». Прошедший праздник в кабинете остаётся
приглушённым — это следует из даты, а не из статуса.

### Р5. Телефон — конструктор блокируем, как в макете

На `< lg` холст не открывается. Вместо него мобильный режим `MobileEdit`:
вкладки «Страница / Подарки · N / Тема», блоки списком карточек с «выше /
ниже», правка текста в textarea, тумблер «Показывать», баннер «Новые блоки
и свободная раскладка — в конструкторе на компьютере» ведёт на
`MobileBlocked`. Создание с телефона — только из шаблона (`MobileStart`,
`MobileTemplate`). Текущий адаптивный холст на узкой ширине убираем.

Кнопку «Прислать ссылку на почту» не делаем и убрали из макета
(`MobileBlocked`, `MobileStart`): почты у вошедших через Telegram нет.
Остаётся «Скопировать ссылку».

### Р6. Подарки: имя дарителя, «Уже подарено», лимит описания

- При брони «Как вас подписать?» + «Анонимно». Другим гостям видно «Дарит
  Аня», владельцу имя не отдаётся — «Маша не узнает, кто что дарит».
- «Уже подарено» ставит владелец на экране «Подарки»: действие в строке
  и «отметить все занятые подаренными» после даты праздника.
- Лимит описания — 1000 символов (`LongText`), бэк сейчас режет на 500.

### Р7. Мелочи

- Новый блок из текста — Ctrl+Enter, как в коде; в `InlineEdit` подсказка
  исправлена.
- В библиотеке 14 блоков, как в `BlockMatrix`: «Дата», «Обратный отсчёт»
  и «Разделитель» из библиотеки убираем, у старых вишлистов они читаются.
- В `MainLight` добавлена кнопка «+ подарок», в `BuilderResize` — вкладки
  «Страница / Подарки».
- Голоса бэк хранит по индексу варианта, а варианты в макете
  перетаскиваются — нужны стабильные id (Б7).
- Поздравления — только текст: тумблер `photos` у guestbook убираем.

## 3. План работ — бэкенд

Порядок важен: Б2–Б5 нужны фронту раньше остального.

### Б1. ~~Статус вишлиста~~ — снято (Р4)

Нумерацию не сдвигаем, чтобы ссылки на задачи не разъехались.

### Б2. Оформление в настройках — S
- `Settings`: `headingFont` (`accent | strict | soft | poster | elegant | classic`),
  `pattern` (`none | stars | confetti | lines`), `mainDreamLarge`,
  `confettiOnReserve`, `liveTimer` (bool).
- Валидация enum, значения по умолчанию, поля в `templates.json` у заготовок.
- Обновляется существующим `PUT /wishlists/:id` (UpdateMetadata).

### Б3. Ряды — формат блоков v3 (Р1) — L
- `Block.Col` 0–2, `Block.ColSpan` 1–3; `Block.Width` (`narrow | full`) для
  одиночного блока.
- `Wishlist.Rows []RowSettings`: `columns` 1–3, `ratio` (`1:1 | 2:1 | 1:2 | 1:1:1`),
  `height` (`equal | auto`), `gap` (`s | m | l`), `mobileReverse` bool.
- `PUT /wishlists/:id/blocks` принимает `{ blocks, rows }` одной транзакцией
  под `If-Match`; ответ отдаёт оба.
- Валидация: блоки не перекрываются, `col + colSpan ≤ columns` ряда.
- `BlocksVersionCurrent = 3`; v2 читается как есть (нет записи — значения по
  умолчанию), запись всегда v3.
- Шаблоны (системные и пользовательские) хранят `rows` вместе с блоками.

### Б4. Секрет до даты — S
- Поля блока вне `data`: `secretMode` (`timer | lock | hidden`), `secretText`.
- Публичная выдача до даты: `hidden` — блок не отдаётся; `lock` — без `data`
  и без `revealAt`; `timer` — без `data`, с `revealAt`. Текст на замке
  отдаётся всегда.

### Б5. Подарки — M
- `isMain` (не больше одного на вишлист — снимать у остальных при установке),
  `sortOrder` + `PUT /wishlists/:id/presents/order { ids }`; в выдаче главный
  первым, дальше по `sortOrder`.
- `gifted` + `giftedAt`: ставит владелец (`PUT /presents/:id/gifted`); на
  подаренном бронь недоступна.
- `PUT /presents/:id/reserve` принимает `{ name?, anonymous? }`;
  `reservedByName` отдаётся гостям и не отдаётся владельцу (Р6).
- `MaxPresentDescriptionLen = 1000`.

### Б6. Ответ гостя — M
- В `data`: `questions [{ id, label, kind: text | number | bool }]`,
  `deadline`, `showGuests`.
- `RSVPResponse.Answers` (jsonb, ключ — id вопроса); валидация по типам.
- После `deadline` — 409 `rsvp_closed`.
- `GET …/rsvp/guests` — имена идущих, только при `showGuests`.

### Б7. Голосование — M
- Варианты со стабильными id: `options [{ id, text }]`. Сейчас голоса по
  индексу — после перетаскивания или удаления варианта голоса перейдут
  на чужой вариант. Миграция: индекс → сгенерированный id.
- `multiple`, `results` (`all | after_vote | owner`), `closesAt`, `guestOptions`.
- `POST …/poll` принимает `{ options: [id] }`; при `after_vote` до голоса
  результаты не отдаются, при `owner` — только владельцу; после `closesAt` —
  409.
- Варианты от гостей — отдельная таблица с модерацией владельцем (как
  гостевая книга).

### Б8. Загрузка картинок — M
- В ответе `/upload`: `width`, `height`, `blurDataURL` (крошечное превью для
  «размытое → чёткое»).
- HEIC: на бэке нужен libheif (cgo), поэтому **рекомендация — конвертировать
  на клиенте** (`heic2any`) и бэк не трогать.
- Обрезка — на клиенте до загрузки, бэку не нужна.
