# Сведение main и редизайна

Дата: 29 сентября 2026. Оба репозитория сведены и закоммичены, **не запушены**.

- фронт: `feature/constructor-wishlist`, мёрж-коммит `5b1693e` (родители `7ea389a` + `7e5d7cd`)
- бэк: `feature/redesign-backend`, мёрж-коммит `1fad254` (родители `4d9f8bb` + `6851bce`)

## Принятые решения

**Модель main — основа, редизайн — надстройка.** Прод живёт на main, ломать его
контракты незачем.

**Блоки — координаты сетки.** `row`, `col`, `colSpan` из main вместо плоского
`position`/`mobilePosition`. Сверху добавлены поля редизайна: стабильный `id`,
`view`, `caption`, `title`, `hidden`, `revealAt`. Координаты меняются при каждой
перестановке, поэтому ответы гостей, голоса и треки привязаны к `id`, а не к
месту в сетке.

**Шаблоны — две разные сущности.**

| | системные | пользовательские |
|---|---|---|
| где живут | `templates.json` рядом с кодом, `go:embed` | таблица в базе |
| кому принадлежат | никому, одинаковы для всех | автору |
| где видны | только `/wishlist/create` | витрина `/templates` |
| что умеют | создать вишлист по заготовке | лайки, публикация, копирование чужого |
| типы | `entity.SystemTemplate`, `SystemTemplate` | `entity.Template`, `Template` |
| маршруты | `GET /system-templates`, `POST /wishlists/from-system-template` | `GET /templates`, `/templates/my`, `POST /templates`, `POST /wishlists/from-template/:id`, лайки |

Клиентский список заготовок `content/templates` удалён: заготовки приходят с
бэка, источник правды один.

**Парсер ссылок удалён целиком.** Маркетплейсы блокируют запросы, работающего
варианта нет. Ушли `usecase/parse`, `pkg/parser`, `entity/parse.go`,
`ParseRateLimit`, маршруты и фронтовый `useApiParseUrl`.

**Что сохранено из редизайна:** три состояния брони («свободен», «вы дарите»,
«уже дарят»), гостевые блоки (RSVP, голосование, плейлист, гостевая книга),
кука гостя, автосохранение с `If-Match`, девять цветовых схем и своя схема,
инлайн-правка текста и меню по «/», кабинет с поиском, леттеринг логотипа.

**Что сохранено из main:** групповые подарки и наборы, пользовательские
шаблоны с лайками, SEO-метаданные и фавиконки, блог, `/wishlist-for`,
онбординг driver.js (перенацелен на живые элементы редактора), баннер кук.

## Переделанное при сведении

- Холст конструктора перестроен под координаты: перенос мышью в конкретную
  ячейку, «+» в пустой ячейке, сдвиг строки вниз вместо затирания соседа.
- Сеточные помощники вынесены в `shared/grid.ts` — это ядро конструктора,
  а не деталь одного компонента. Покрыты `tests/grid.test.cjs`.
- `addBlockAfter` и `duplicateBlock` теперь ставят блок строкой ниже и
  сдвигают нижних соседей.
- Логика брони и складчины вынесена в `use-reservation.ts`; раньше была
  продублирована в карточках и в списке и успела разойтись.
- Загрузчик TS-модулей для тестов вынесен в `tests/load.cjs`.
- Примеры `content/occasions` получают `id` блоков и счётчики при экспорте,
  а не руками в литералах.

## Проверено

- Бэк: `go build ./...`, `go vet ./...`, `go test ./...` — зелёные.
  `pkg/imageconv` и `pkg/minio` локально не собираются: `chai2010/webp` требует
  cgo, а в оболочке нет компилятора C. В Docker собирается.
- Фронт: `tsc --noEmit` чисто, 51 тест проходит, `eslint` без ошибок.
  `next build` компилируется и генерирует все 28 страниц; сборка standalone
  падает на симлинках — это ограничение Windows, не код.

## Что осталось руками

- Проверить конструктор в браузере: перенос блоков, «+» в пустой ячейке,
  меню по «/», предпросмотр на ширине телефона.
- Проверить создание вишлиста из системной заготовки и из своего шаблона.
- Интеграционные тесты бэка (`//go:build integration`) требуют Docker.
- Фото от гостей в гостевой книге не делаем: `/upload` под JWT, публичная
  загрузка — отдельное решение про лимиты и модерацию.
- Загрузка в складчину (`join`/`leave`) на бэке не привязана к гостю — счётчик
  общий, «я уже отметился» помнит только localStorage браузера. Так было на
  проде; привязать к куке гостя можно отдельной задачей.
